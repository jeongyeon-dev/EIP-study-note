**9-1. 단원**    
-1. 개념: 5회 
스니핑 => 수동형, 엿 듣는 형태로 정보 탈취 || 스푸핑(위조/조작으로 탈취), ? 스머프(일종의 DoS, Echo 패킷 조작)    
가용성 => 권한자가 편하게 데이터 접근/조작 || 무결성(비권한자로 부터 보호), 기밀성(비공개, 노출 차단)  
3A => Authentication(사용자 식별), Authorization(권한 부여), Accounting(관리?)  
해시 => 임의의 길이 -> 고정 길이로 단방향만  
스머프/스머핑 => 일종의 DoS, Echo 패킷을 조작, 브로드캐스팅.. 타겟 서버 마비  

-2. 공격 종류: 5회  
DoS > 랜드 어택(수신=발신 -> 되먹임) || 고갈형(SYN/UDP 플러딩), 위조형(스머프, 랜드어택), 패킷(티어 드롭, 죽음의 핑, 봉크/보잉크)  
? > SQL injection(악의적 SQL 구문 삽입 -> DB 접근 -> 정보 탈취)   
? > 세션 하이재킹(세션 관리 취약점 이용, 재연결을 공격자에게)  
네트워크 > ARP 스푸핑(MAC 주소 변경해 패킷 가로챔) || 스니핑, 패스워드 크래킹(사전/무차별/패스워드 하이브리드/레인보우 테이블), IP 스푸핑(패킷의 IP 주소 위조), 트로이 목마(숨겨져 있음), ICMP?  

-3. 암호화 알고리즘 종류: 5회 
해시 > MD5(MD4 발전형, 128비트) || SHA(-1: 160비트, -256/384: AES 대응 길이), HAS-160(국내 표준) 
대칭키 > AES(DES 극복, 64비트) || DES(IBM 개발 -> NIST 발표, 16라운드?), 국내: SEED(한국인터넷진흥원), ARIA(국정원 + 산학연구협회. Academy + Research Institute + Agency), IDEA(스위스.. 과거: IPES), Skipjack(미 국가안보국, 카드 형태) .. 2번 출제!  
대칭&비대칭 > 대칭: DES, AES, SEED, ARIA, 비대칭: RSA, ECC || RSA(Rivest, Shamir, Adleman -> 소인수 분해 수학적 알고리즘), ECC(타원곡선에서 이산대수)  

-4. 보안 정책: 2회 
DAC => Discretionary(임의적 -> 자원소유자 맘/신분이 근거) || MAC(강제적 -> 등급, Rule-Based 통제), RBAC(역할 기반 -> 할당된 역할에 기반) .. 2번 출제!   

-5. 보안 기술: 2회
SSO => Single Sign On(한방에) || OAuth(소셜 로그인), 커버로스(MIT Athena 프로젝트, 대칭키 프로토콜)   
OAuth => 구글/페이스북 등 외부 계전 기반으로 간편하게 사용  

-6. 보안 프로토콜: 2회  
L2TP(Layer 2 Tunneling Protocol -> L2P + PPTP) || PPTP(마소가 개발, ip헤더로 캡슐화?), L2F(시스코사가 개발, 다자간 통신)  
IPSec(Internet Protocol Security -> 공용 인터넷 망을 사설 VPN 처럼?)

**10-1. 단원**  
-1. 개념: 2회  
살충제 패러독스 => 살충제와 같이, 동일 한 케이스로 반복하면, 새로운 버그를 찾지 못함  
블랙박스 테스트 => 동치분할/경계값 분석 등이 있음, 내부 안보고 사용자 요구사항 -> 결과 비교    

-2. 테스트 종류: 11회
-2-1. 화이트 박스:  
구문 커버리지(모든 문장) and 결정 커버리지(모든 if 참/거짓) and 조건 커버리지(if 문 안의 개별 참/거짓)  
분기 커버리지 => 분기(결정)&조건 -> 분기는 if문 하나/조건은 if문 내 세부 조건 -> Yes-No를 한 번씩은 다 지나야 함  
조건 커버리지 => 개별 조건식 최소(참/거짓) || 조건/결정(각각 참/거짓), 변경 조건/결정(개별 조건이 독립?), 다중 조건(모든 조합)  
변경 조건/결정 커버리지 => 개별 조건이 변하는게 결정에 영향을 주는지  
구문(statement) and 분기/결정(branch/decision) and 조건(condition)  

-2-2. 블랙 박스:  
동치 분할 테스트 => input이 간격 기준 || 경계값 분석, 원인-결과 그래프(입-출 관계를 그래프로), 결정 테이블(여러 조합 -> 결과), 상태 전이(상태 바꿔가면서) .. 3번 출제!
경계값 분석 테스트 => -1, 0, 1.. 뭐 이런 예시  
원인-효과 그래프 => 입-출 관계 그래프 -> 영향 분석  
블랙박스 테스트 종류(원인-효과, 경계값, 동치분할)  

-2-3. V 모델: 3회  
단위 테스트 and 통합 테스트(인터페이스 간?) || 단위 -> 통합 -> 시스템 -> 인수(알파 -> 베타) .. 2번 출제!  
알파(개발자랑 같이) and 베타(사용자 오류 -> 개발자에게)  

-3. 테스트 세부: 4회  
테스트 조건(어떤 종속성) and 테스트 데이터(입력값) and 예상 결과(기대값) || 테스트 목적, 테스트 환경

-4. 틈새 지식: 2회  
샘플링 오라클 => 몇 개의 입력값만 || 참 오라클(전부), 휴리스틱/일관성 검사 오라클  
회귀 테스트(오류 수정 -> 새 버그 있나?) || 회복(고의로 부하), 안전(불법 잘 막나?), 성능, 구조(내부 설계 보자..), 병행(변경 후 이상없나?)
