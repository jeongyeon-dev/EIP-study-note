**객체 지향**  
객체 지향 "특성"이라고 함, 사용할 수 있는 기능.이다..    
캡슐화(연관된 것 끼리 묶은 다음 외부와 경계 만듦, 정보 은닉과 관계)  
상속성(상위 -> 하위로 재정의 없이 물려받아 사용)  
다형성(상속이 좀 유연하게 됨? -> 오버로딩 vs 오버라이딩)  
추상화(공통의 형질을 추출하여 추상 클래스를 만듦)  

객체지향 설계 원칙도 있음.. 
설계 원칙은 위의 4대 특성을 이용해서 설계할 때 준수해야 할 것들..  
S(Single Responsiblity P.)- 단일 책임: 하나의 클라스=하나의 목적/책임 .. 캡슐화  
O(Open Closed P.)- 개방 폐쇄: 기존 것 수정 없이 새롭게 확장 용이 & 변경에는 닫혀야 .. 다형성/추상화  
L(Liskov Substitution P.)- 리스코프 치환: 하위는 상위 것으로 대체 가능해야 .. 상속성/다형성  
I(Interface Segregation P.)- 인터페이스 분리: 클라스는 사용 안하는 인터페이스 구현 x  
D(Dependency Inversion P.)- 의존 시, 추상?을 매개로 관계를 느슨하게 할 것  

객체 지향 분석 방법론(OOA:Object Oriented Analysis)  
곧 개발할 시스템을 객체 중심으로 분석하는 방법.이라 한다..  
야곱슨: 유스케이스를 근간으로 활용/기능적 요구사항 중심  
럼바우: 객체 모델링(E-R diagram) -> 동적 모델링(상태 diagram) -> 기능 모델링(자료 흐름도)  
부치: 설계 문서화 강조? 다이어그램 중심으로 개발하는 방법론
