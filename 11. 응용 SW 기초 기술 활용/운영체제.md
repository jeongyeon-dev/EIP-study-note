Malloc에서 메모리 할당 기억나나.? .. 주 기억(램)에서 일어나는 일    
최초 적합(First Fit), 순회하면서 먼저 핏이 맞으면 바로 할당하는 방식이고,  
최적 적합(Best Fit)은 가용 공간.. 중에서 비슷한 공간을 골라서 할당,  
최악 적합(Worst Fit)은 가장 큰 공간에 할당해서 남는 공간(내부 단편화)가 짱 큰 상태.  
.. 외부 단편화는? 남은 메모리가 작아.. 새 메모리를 할당하지 못하는 상태  

이후 "할당 기법"과 "교체 기법"이 나오는데,  
차이: 전자는 맨 처음에 할당을 할 때(연속적으로 붙일 지, 분산 시킬지) 정하는 거고,  
후자는 메모리 다 찼을 때, 어떤 방식으로 이미 할당된 것을 퇴출시킬지 정하는 것.  

**교체기법** 시험에 자주 나오니 중요!  
FIFO: 가장 오래된 녀석을 퇴출(적재될 때 그 시간을 기억해야 함)  
LRU: 오랫동안 사용하지 않은 녀석을 퇴출(마지막 사용 시간을 기억해야 함)  
LFU: 가장 덜 사용한 녀석 퇴출(해당 시점까지 사용한 횟수를 기억해야 함)  
-- 여기서 부터는 연산형 문제에 안나옴 --  
OPT(OPTimal Replacement): 앞으로 가장 오랫동안 사용을 안할 페이지를 예측한다고 함  
NUR(Not Used Recently): LRU의 변형, 참조/변형 비트? 같은 것을 사용  
SCR(Second Chance Replacement): FIFO 보완, 참조 비트?로 자주 사용하는 것 교체 방지  

Trashing: 페이지 교체 시간 > 실제 실행 시간. 되는 현상  
Working Set: 많이 참조되는 페이지를 "세트"로 묶어서 관리.. 다만 만들고 운영하는데 비용이 듦  
Locality: 최근에 사용된 곳을 계속 참조하는(Temporal), 접근 주소 인근도 다 접근하는(Spatial)  
=> 지역성이 단순히 같은 주소를 반복하는 것을 의미하지 않음!

다음은 **프로세스**이다  
얘는 "생애주기"가 있다: 생성 => 준비 => 실행 => (완료 or 대기 => 다시"준비"로)  
"실행"은 CPU를 할당받아 작업을 하는 상태를 의미.  

준비: CPU를 언제든지 점유를 할 수 있는 상태.  
실행 => 준비: "할당 시간 초과"되어 자동 CPU 반납하는 것.  
실행 => 대기: 예시로, 파일 읽기(I/O)를 요청 했는데 데이터 준비 안됨. 즉, "입출력 발생"  

대기 => 준비: 입출력이 종료된 이후 언제든지 CPU 점유가 가능한 "Wake-Up"을 함.  
준비 => 실행: "디스패치"라고 함. 문맥교환?이 일어난다고 함.  
<br>

**프로세스 스케줄링**이랑 페이지 교체 기법 등이랑은 차이가 뭐지?  
먼저.. 한정된 공간에서 낮은 우선순위를 교체하는 것은 같다. 다만, 페이지는 작은 단위로..  
이 페이지들이 모여서 하나의 프로세스를 구성을 하게 된다. 단위 차로 일단 이해.  

선점형 스캐줄링(높은 priority가 중간에 자리 뺐음) vs 비선점형 스캐줄링(먼저 온 놈이 임자)  
.. 스캐줄링 알고리즘은 시험에서 **연산형 문제**로 등장한다.. 유형별:  

SRT(Shortest Remaining Time first):  
가장 짧은 수행 시간이 걸리는 process이면(대기 큐에 있으면), 언제라도 선점.  
문제는 각 process별: 도착 시간, 서비스 시간. 으로 제공.  
여기서 서비스 시간이 소모되어 해당 시간에 남은 시간=수행 시간. 이며, 이를 기준을 선점 발생.  
..또한 반환 시간(종료 시간 - 도착 시간), 대기시간(반환시간 - 서비스 시간)을 구하는 것도 요구.  

다단계 큐(Multi Level Queue):  
잘을 모르겠는데, 작업을 분류 => 여러 개의 큐에 넣고, 각 큐가 자기만의 스캐줄링을 한다고..  
연산형 문제 안나옴.  

다단계 피드백 큐(Multi Level Feedback Queue):  
"피드백"이라는 말이 들어간 이유 => 여러 개의 큐에서 process가 들어갔다가 다른 곳으로 이동  
뭐.. 실행시간이 길어질 수록 낮은 우선순위 큐로 이동한다나..  
연산형 문제 안나옴.  

라운드 로빈(RR: Round Robin):  
CPU에 시간 할당량이 정해져 있음. 정해진 시간에 다 못한 process는 큐의 뒤에 들어간다.  
각 process별: 도착 시간, 서비스 시간. 이 제공.  
<br>

다음은 **비선점형 스케줄링**이다.  

FIFO: 페이징 쪽과 동일한 명이나, "퇴출"이 아니라 먼저 도착한 놈이 끝 까지 점유하는 것이다.  
연산형 문제로 "반환 시간"과 "대기 시간"이 나올 가능성 있음.  
FCFS(First Come First Serve)와 동일  

SJF(Shortest Job First):  
SRT와 다르게 비선점형, 이미 정해진 "정도"로 선점해 버린다.  
새 process가 들어갈 자리가 생겼을 때 => 서비스 시간이 짧은 녀석이 우선 먹는다.  
=> 우선순위가 낮은 녀석이 무한정 기다리는 "기아 현상"이 발생이 가능.  

나머지로, HRN(Highest Response Ratio Next)는, SJF의 기아현상 보완책으로..  
작업(서비스?) 시간을 우선으로 둔 것이 아닌, `(대기시간 + 서비스 시간)/(서비스 시간)`을  
중심으로 우선순위를 조정함.
