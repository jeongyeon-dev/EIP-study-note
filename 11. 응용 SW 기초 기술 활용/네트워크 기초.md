**네트워크에서의 프로토콜**  
프로토콜.. 알다시피 "통신 규약"이다. 전송하고, 도착했는지 확인하고, 잘 안되었으면 재전송 하고

좀 헷깔리는데.. "제어 정보" 즉, 수신 쪽에서 어떻게 반응해야 햐는지 <u>의미</u>가 있다.  
예시로 GET 메서드. 마지막으로 <u>타이밍</u>은, 전송 속도 및 순서 규정인데..

*3계층(네트워크)에서의 프로토콜*  
주로 "라우터"에서 수행하는 것으로 이해를 하면 된다. LAN과 LAN 사이를 연결하는 것.  
경로를 설정해야 하는 만큼, <u>라우팅</u>, <u>패킷 포워딩</u>, 인터 네트워킹.. 용어를 씀.  

사용하는 프로토콜.. 아는 것 부터 써보자.  
ARP(Address Resolution Protocol): IP주소를 물리적인 MAC 주소로 변환하는 규약.  
RARP: 반대로(Reverse), MAC 주소를 IP 주소로 변환.  
NAT: 사설 IP => 공인 IP.. 왜? IPv4 주소는 부족하고, 공인 IPv4를 사용해도 내부망에서는 다름.  

IP: 헷깔리는데.. IP 주소를 규약에 맞게 정의하고, 목적지 정보 등 가짐.  
라우팅 프로토콜: 라우터 간 통신?하여 최적의 경로를 설정하는 규약.  
ICMP(Internet Control Message P.): 전달 과정에서 발생한 오류를 전송하는 규약.  
IGMP(Internet Group Management P.): <u>멀티케스트</u>에서 탈퇴/가입 등을 하도록 하는 규약.  

* 멀티케스트: 특정 그룹(Group)에 속한 장치들에 동일한 데이터를 보내는 것  
<br>

**IPv4**  
유명한 IPv4이다.. 32비트 주소체계, 43억개 주소 수로.. 고갈 위기.  
주소체계는 10진수로 총 12자리, 4분할: 0.0.0.0  
여기서.. 자유롭게? 사용할 수 있는 분할 영역 갯수에 따라 A => B => C 클라스로 나뉨  

*서브네팅*  
알고 있지만 난해한 것. IP 주소를 절약하는 법이라고.. 효율적으로 IP 주소 분배하는 방법.  

계산하기(Fixed-Length Subnet Masking 방식으로):  
2진법으로.. 8개.8개.8개.8개, 인데.. 서브넷은 $2^n$ 갯수로만 나눌 수 있다.  
서브넷 주소는 만약 할당된 2진법 자리가 8개이면, 좌측 $2^n$ 갯수의 n개 차지.  

예:  
3개의 서브넷이 필요하다면 $2^4$ 하여 16개의 서브넷 생성.  
제공된 2진법 자리가 8개면 좌측 4개가 서브넷 주소. 나머지 4개가 호스트 IP 주소.  
여기서 앞뒤 끝 단은 사용하지 못한다: xxxx0000, xxxx1111 => 각각 네트워크/브로드캐스트 주소  

문제에서:  
서브넷 마스크: 어디까지가 IP 주소인지 => 255.255.255.192 => 뒤 6개가 할당된 것  
네트워크 주소: 6개 뒤를 뺀 나머지를 의미 => 서브넷으로 나눈 2개도 주소에 포함.  
서브넷 사용 자릿수 추론하기 => 32/4 = 8개로 나눠, 네트워크 주소 중 사용하는 여분이 서브넷 것  
<br>

**IPv6**  
128비트 주소 체계. 새로운 주소체계로 $2^{128}$개라는 어마한 숫자..  짤막하게 지원하는 기능:  
Plug&Play: 네트워크에 접속하는 순간 IP 주소를 지원받음.  
Ad-hoc 네트워크: 자동으로 지원. 이것이 무엇인지는 추후 설명이 있을 것.  

듀얼스택: 한 장치에 IPv4, IPv6 프로토콜이 모두 탑재.. 경우에 따라 각각 선택.  
터널링: 중간에 IPv4 네트워크를 거쳐야 할 때, 그 네트워크에 "터널"을 만들어 관통.  
주소 변환: IPv4 <-> IPv6 게이트웨이를 사용, 패킷을 변환시킴.

*라우팅 프로토콜 세부적으로 보기*  
위에서 학습한 "라우팅 프로토콜"을 세부적으로 종류가 있다. 이에 대해 정리하는 곳.  
먼저 전송 전에 미리 정하는 **정적**라우팅, 그리고 실시간으로 변하는 **동적**라우팅이 있으며,  
주로 동적 라우팅이 설명이 된다..  

내부 라우팅/외부 라우팅이 있는데, 라우터 군집(Autonomous System: 자율 시스템)으로,
공통 라우팅 정책으로 운영되는 곳 내에서 하는 것을 "내부" 그 바깥을 "외부"라 한다.  
당연, 군집 내에서 라우팅이 활발?하니 내부 라우팅 쪽이 프로토콜이 많을 것.  
내부(Interior Gateway Protocol: IGP) <=> 외부(Exterior " : EGP)  

RIP(Routing Information Protocol): 거리-벡터 알고리즘?을 사용.  
벨만-포트 알고리즘 사용. 이해는 못하나 암기만 하면 된다?고.. 15홉 제한.  

OSPF(Open Shortest Path First): 링크-상태 알고리즘?을 사용.  
RIP 단점 보완했다고 한다.. 홉 무제한, "다익스트라 알고리즘"사용.  

* 링크-상태(다익스트라) 알고리즘 => 전체 네트워크 지도를 기반으로 node를 순회하여 거리 계산  
* 거리-벡터(벨만-포드) 알고리즘 => 잘 모르겠어나, 다음 node를 건너가면서 비용 add.  

BGP(Border Gateway Protocal): 경로 벡터 알고리즘?을 사용.  
이름에서 보듯, 외부 라우팅이다. 당연 ISP 사업자들 간 간의 TCP 연결로 사용됨.

*7계층(응용)의 프로토콜*  
너무 많다.. 대표적인 것으로..  
HTTP(Hyper Text Transfer Protocol): 링크를 통해 이동 가능한 "하이퍼 텍스트" 관련.  
HTTPS(HTTP over Secure Socket Layer): HTTP에서 통신이 암호화 되어 보안 강화.  

FTP(File Transfer Protocol): 단어에서 그대로, 파일 전송 목적.  
SMTP(Simple Mail Transfer Protocol): 메일 전송 목적.  

Telnet: 다른 컴퓨터 원격으로 접속.  
SSH(Secure SHell): Telnet과 같이 원격 컴퓨터 접속. 다만, 키 인증 및 보안 강화.  

DNS(Domain Name System): 도메인(google.com)을 실제 IP 주소로 바꿔주는 것.  
<br>

이제는.. 네트워크 전달 방식이다.
어느 계층이냐는.. 방식을 어디에서 적용하냐에 따라 다르다.  
서킷 교환(회선 교환): 물리 계층에서 전송 경로(회선)을 정해주는 방식.이라 할 수 있으며,  
패킷 교환: 경로 자원을 공유하면서 패킷 단위로 보내는 만큼, 주로 3계층.이라 할 수 있다.

이 패킷도.. 교환 방식이 세부적으로 다르다.
-1. 가상회선(Virtual Circuit): 미리 논리적인 경로를 만든다. 그 경로를 통해서 전송  
-2. 데이터그램(Datagram): 패킷을 독립적으로 보낸다. 각각 보내져서 조립됨.  

에드 혹 네트워크(Ad-hoc Network):  
기지국, 엑세스 포인트 같은 기반 네트워크 장치 없이, 무선 인터페이스를 사용하여 서로 통신.  
이렇기 때문에 "네트워크 토폴로지"가 동적으로 시시각각 변화함. => 전쟁/군사용으로 사용
