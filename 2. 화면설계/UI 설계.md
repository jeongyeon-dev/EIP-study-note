이쯤 되니 과목명의 "화면"에 대한 정의가 좀 혼동이 온다.  
UI와 같은 시각적인 보이는 것을 의미하기 보다는, 시각적으로 설계하는 것을 통틀어서 "화면"  
으로 정의하는 것이 아닐까 싶다.  

UML(Unified Modeling Language)  
소프트웨어를 개발 할 때, 어떻게 구성할 지 표현하는, 즉 모델링 하는 언어로  
이 또한 규격화 되어 있는 형태라고 한다.  

종류가 다양한데(이걸 외워야 한다..)  
크게 분리하면 구조적(정적) 다이어그램과 행위적(동적) 다이어그램으로 나눈다고 한다.  

즉, 정적. 움직이지 않고 전체 틀을 도식화 하는 것을 "구조적 diagram"이라 표현하는 듯 하다.  
책에는 많은 것들 중에 대표적인 것들을 상세히 설명되어 있는데 이를 각각 정리하자면:  
  

**정적 다이어그램들**  
클래스 다이어그램:  
코딩할 때 정의하는 class를 기준으로 도식화를 하는 듯 싶다.  
-당연 클라스 명  
-클라스가 가진 요소들(속성)  
-안에서 일어나는 행동(연산/메서드)  
-클라스 요소 들의 접근 범위.. 예를 들어 public/private를 결정하는 "접근 제어자"등을 담는다.  

클라스 간의 관계 표현은?.. 방식도 있다  


패키지 다이어그램:  
얘는 클라스랑 뭔 차이일까? 클라스들이 뭉쳐서.. 더 큰 단위인 "패키지"기준으로 한 것.  
예시 코드가 있다:  
```
    ┌───────────────────────┐
    │     user 패키지        │
    │                       │
    │  UserController       │
    │  UserService          │
    │  UserRepository       │
    │  User                 │
    └───────────┬───────────┘
                │ 의존
                ▼
    ┌───────────────────────┐
    │     order 패키지       │
    │                       │
    │  OrderService         │
    │  OrderRepository      │
    │  Order                │
    └───────────────────────┘
```
보면 여기 각각 낱개의 Controller 등도 안에 클라스가 있다. 이를 기능 단위로 묶어서 표현한 듯.
