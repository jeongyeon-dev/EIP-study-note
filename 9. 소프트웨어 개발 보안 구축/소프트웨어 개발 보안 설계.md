여기서 로그인 사용자 말고는 못 하니까 **기밀성**, 특정 유저에게만 접근이 가능하며,  
이렇게 <u>인가된 사용자</u>말고는 조작이 불가하므로 데이터 자체는 **무결성**이 있다.  
또한, 인가된 사용자만 조작이 가능하므로 데이터 자체는 **가용성**이 있다(어? 아? 다른 건지..)

공격 종류와 유형 정리에 대한 내용들..  

**DoS(Denial Of Service)** 공격이란?  
대상을 <u>서비스(를) 거부</u>하도록 만드는 공격: 종류가 여러 가지 인데 구심점을 잡자면..  

-1. 자원 고갈형.. 대량 요청으로 서버 자원 소모 유도  
SYN 플러딩(Flooding): TCP에서 새 연결 요청을 하는 SYN패킷만 무수히 보내고, 응답은 씹음  
UDP 플러딩(Flooding): 출발지를 임의의 서버로 변조, 대량으로 보냄 => 임의와 함께 자원 고갈  
  
-2. IP 위조·반사형.. IP 주소를 조작해 비정상적인 상호작용 유발  
스머프(Smurf): 아래와 같은 형태로, 피해 서버가 발신한 것 처럼 IP 출발지 주소 조작.  
```
                  ┌─ 호스트 A ─┐
공격자 → 브로드캐스트 ─ 호스트 B ─┼→ 피해 서버
                  └─ 호스트 C ─┘
```
랜드 어택: 수신지=발신지 IP 패킷을 보내 서버가 자기 스스로 되먹임 하다가 뻗음.  

-3. 비정상 패킷 처리.. 패킷 처리 과정에서 시스템이 오류가 나도록 유발  
죽음의 핑: 패킷을 아주 크게 만듦 => 서버가 조합하다가 과부화(버퍼 오버플로우) 걸리도록.  
티어 드롭: 패킷들의 접합점(Offset)을 중첩되도록 조작 => 조립 시 오류 발생해서 마비되도록.  
봉크: 티어 드롭과 유사, 패킷을 모두 1번이다!하면서 보내서 서버가 헷깔리도록.  
보잉크: 제대로된 순서로 패킷을 보내다가.. 갑자기 순서가 이상한(ex. 중복) 걸 섞어서 보냄.  
<br>  

이제 다음은 **DDoS(Distributed DoS)**이다. 
좀비 컴퓨터라고 들어봤나? 공격자가 다수의 컴퓨터를 악성코드로 감염시켜 피해 서버를 공격함.  
용어도 나오는데..  얘는 일단 스킵하기로!

DRDoS(Distributed Reflection DoS)공격:  
단어의 의미를 찾아보자.. Reflection(반사)의 의미 => 출발 I   
뭔가 SYN 플러딩이랑 비슷하지 않나? 낱개 단위로 본다면. 위의 스머프도 DRDoS의 일종으로 보기 가능  

extra: 세션 하이재킹: 로그인 시 발급받는 세션 ID를 탈취해서 서버가 오인하도록 함.  
<br>

다음은 **어플리케이션 공격**  
왜 어플리케이션 인가?.. 어플리케이션(응용) 계층에서 일어나기 때문. 예시:  
|공격명|설명|
|:---|:---|
| SYN Flooding | 전송 계층(L4)의 TCP 연결 과정 공격 |
| UDP Flooding | 전송 계층(L4)의 UDP 패킷을 이용한 공격 |
| HTTP GET Flooding | 응용 계층(L7)의 HTTP 요청 처리 과정 공격 |

.. 공격 종류를 여기서도 암기해야 한다. 범주화 해서 설명하자면,  
-1. 대량 요청형: <u>HTTP요청을 대량</u>으로 보내 서버 과부화.  
HTTP GET 플러딩: 말 그대로 GET을 무수하게 요청하여 서버 자원 소진시킴.  
HULK DoS: 위의 것의 변형, 요청을 다양화(URL)하여 캐시 효과를 줄여서 서버 자원 소진시킴.  

-2. 저속 통신형: <u>HTTP 요청을 끝내지 않고</u> 자원을 오래 점유해 서버 소진.  
Slowloris(Slow HTTP Header DoS): 헤더 끝을 보내지 않고 뻐겨서 서버 대기 상태 유지.  
RUDY(Slow HTTP Post DoS): 헤더 이후 본문을 찔끔찔끔 보내서 서버 대기 상태 유지.  
Slow HTTP Read DoS: TCP인 만큼 "클라" 쪽에서 수신 윈도우(받는 정도)를 극소 상태로 알림.  

-3. 연산 자원 고갈형: <u>HTTP Post 등의 방식으로 </u>서버의 처리량을 대폭 증가.  
Hash DoS: 해시 충돌이 일어나는 지점을 집중적으로 요청하여 서버 처리량을 늘림.  
<br> 

**네트워크 공격**  
위 처럼 "네트워크 계층(L3)"을 공격하는 것을 의미하지 않는다. 
일단 네트워크 통신이나 프로토콜을 이용한 공격이라는데.. 추후 더 이해하기로..  
어플리케이션 공격과 위의 DoS/DDoS가 연관되어 있지만, 여기는 새로운 단원이다(별개의 목적).  

공격 종류를 범주화 해서 이해해보자,  
그에 앞서 용어 설명: 스니핑(Sniffing) => 엿듣기, 스푸핑(Spoofing) => 속이기(위조)  

-1. 정보를 몰래 수집하는 기법  
스니핑: 수동적 공격기법, 데이터만 몰래 들여다보는 방식으로 "네트워크 스캐너, 스니퍼"를 사용.  

-2. 출발지 신원/주소/경로를 위조하는 기법  
IP 스푸핑: IP 패킷의 출발지 주소 위조 => 다른 IP(인증된 사용자)에서 온 것처럼 속임.  
ARP 스푸핑: 이번에는 MAC 주소(ex. 공유기인 것처럼 위장)를 위조 => 정상 MAC으로 속임.  
ICMP Redirect: L3 계층에서 라우팅 경로를 변경하도록 유도? 한다고 함.  

-3. 인증정보(비밀번호)를 알아내는 기법  
패스워드 크래킹: 간단하게, 하나 하나 예상하고 짜맞춤 하는 <u>사전 크래킹</u>가 있으며,  
무식하게 그냥 때려 맞추는 <u>무차별 크래킹</u>, 이 둘을 합친 <u>패스워드 하이브리드</u>,  
해시값을 미리 생성을 하여 역으로 찾는다는 <u>레인보우 테이블 공격</u>이 있다.  

-4. 악성코드로 침입하는 기법  
트로이 목마: 겉보기에는 정상적인 프로그램인데 안에 악성코드 있어 실행되어 악용함.  
<br>

그 외의 기타 내용 같음, 빠르게 넘어가기로.  
버퍼 오버플로우 공격: 메모리에는 버퍼(Buffer)와 같이 할당된 영역이 있다. 이를 넘치도록 해  
시스템이 이상을 일으키는 공격인데, 주 영역인 Stack 오버플로우, Heap 오버플로우 공격이 있음.

지금까지 공격 방식/기법에 대해 훑어보았다. 이번엔 인가된 사용자만 시스템이 접근 허용하는  
**인증 및 접근 통제**에 대한 개념이 나온다.  

인증 방식도 분류화 되어 있다. 통상 ID/PW, 사용자 머릿속에 기억하고 이를 사용하는  
**지식기반 인증**, 물리적으로 하드웨어에 있어야 가능한(ex. 공인인증서)  **소지기반 인증**,  
아얘 사용자 지문 등으로 **생체기반 인증**이 있고, 사용자의 서명, 몸짓 등 "행하는 것"을  
기준으로 삼는 **특징기반 인증**이 있다.  

서버 접근 통제를 차등화 및 부여하는 방식이 종류가 있는데,  
DAC(임의적 ..) => 소유자 재량(그러니까 임의), 소유자가 타인 지위 신분을 보고 결정  
MAC(강제적 ..) => 내부적인 보안 등급 등이 시스템에서 강제됨.. 좀 혼란?  
RBAC(역할 기반 ..) => 이미 역할별로(ex. 인사팀) 권한이 있고, 그 역할 부여하면 해당 권한으로 감

**암호**  
평문 =(암호화)=> 암호문 =(복호화)=> 평문: 양방향 방식으로.. 일방향은 복호화가 안됨.  
암호화/복호화 키가 동일하면 "대칭 키", 다르면 "비대칭 키"  
비대칭 키는 "공개 키"와 "비밀 키"가 있음.. 왜? => 좀 더 발달한 방식이다.. 뭐.  

**대칭 키** 암호화 알고리즘 종류.. "암기"할 것.  
DES(Data Encryption Standard): 1975년.. 미국 연방 표군국.. IBM.. 에서 개발  
↓  
-1. AES(Advanced Encryption Standard): DES를 극복하기 위해, 미국 연방 표준국.. 에서 개발.. 2001년..  
-2. IDEA(International Data Encryption Algorithm): DES 극복, 스위스 연방기술 기관..  

SEED: 1999년.. 한국 인터넷 진흥원.. 개발  
ARIA(Academy Research Institute Agency): 국정원 + 산학연구협회 2004년..  

*기타.. 잘 모르겠음*  
LFSR(Linear Feedback Shift Register): 선형 함수로 계산 + 시프트 레지스터? ..  
Skipjack: 미 국가안보국.. Card에 칩 형태로 개발됨  
<br>

**비대칭 키** 암호화 알고리즘..  
디피-헬만(Diffie-Hellman): 최초 공개키 알고리즘 W.Diffie와 M.Hellman이.. 개발..  
RSA(Rivest-Shamir-Adleman): MIT 수학교수(Rivest, Shamir, Adleman)이.. 개발.. 1975년.. 소인수 분해..  
↓ 
ECC(Elliptic Curve Cryptography): RSA 암호 방식에 대안, 1985년, 타원곡선 -> 이산대수..  

ElGamal: T.ElGamal 이 개발.. 1984년.. 
<br>

**해시** 알고리즘.. 복호화 불가능, 그냥 서로 같은지 확인용  
MD4(Message-Digest algorithm 5): MD4를 개선한 알고리즘, 1991년  
SHA-1(Secure Hash Algorithm): 1993년, 미 NSA, 160비트 해시값 생성  
SHA-256.. : SHA 종류 중 하나, AES의 키 길이인 128, 192, 256비트에 대응하기 위해 "출력 길이"늘린 것  
HAS-160: 국내 표준 서명 알고리즘, MD5 + SHA1의 장점만 가져옴  
HAVAL: 1024바이트 단위로 처리하나 -> 가변 길이(128, 160, 192..)로 선택 가능

*암호화 전송..?*  암호화 알고리즘을 통해 암호화 하여 전송하는 기술  
PPTP(Point to Point Tunnel Protocol): 3계층 라우터가 읽을 수 있도록 패킷 안에 정보를 넣음(터널링)  
L2F(Layer 2 Forwarding): 2계층(데이터 링크)에서 사용하는 프로토콜.. 하나의 터널에 여러 개  
L2TP(Layer 2 Tunneling Protocol): L2F + PPP  
**IPSec(Internet Protocol Security)**: 3계층에서, 전송모드(페이로드 보호) <-> 터널모드(전체 감쌈)
