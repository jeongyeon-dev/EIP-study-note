여기선 테스트 종류를 암기하여 답을 내는 기출 문제들이 다수이다.  

가장 크게.  
**화이트 박스 테스트**: 테스트 시, 프로그램 내부에서 실제 어떻게 돌아가는지 알고 있으며, 이를 검사.  

종류별로 다양하다.. 보통 커버리지.. 테스트를 얼마나 수행했냐가 기준이 됨  
구(문 커버리지): 모든 명령문(코드)를 한번 이상 실행되어 함  

```
if(a > 0 && b > 0)
```
조건 커버리지: 위에서 (a > 0), (b > 0) 개별 조건식들이 참/거짓을 한 번씩은 해야 함 => 최종 if 판별 신경 x  
결정 커버리지: 위의 구문에서 if 전체에서 참/거짓이 한 번씩은 함 => 총 2번.. "결정"에 요인만 판별  

조건-결정 커버리지: 개별 조건을 검증하면서 동시에 결정도 참/거짓 분기가 나와야 함  
변경 조건-결정 커버리지: 한 조건만 바뀌어 결과를 바뀌는지 확인.. 모든 조합은 아님  

다중 조건 커버리지: 모든 조건의 조합을 테스트 해야 함 => $2^n$개.. 가장 많음!  
.. 나머지 잡다?한 것은 일단 생략 ..  
<br>

**블랙 박스 테스트**: 반대로 얘는 안을 보지 못한다. 대신 결과값을 통해 추론 및 검증.  
동등 분할 "(Equivalence Partitioning): 값이 일정한 간격으로 띄워서 입력한 다음 테스트  
경곗값 분석 "(Boundary Value Anal.): 판별 경계가 되는 곳을 집중/미세하게 입력해서 테스트  
원인-결과 그래프 "(Cause-Effect Graph): 입력값 => 출력 관계를 그래프라던지 분석해서 좋은 test case 선정?  
오류 추정 "(Error Guessing): 개발자가 범할 수 있는 실수를 추론 => 이에 맞게 테스틑 설계  
비교 "(Comparison): 여러 버전의 program에 동일한 입력값 넣은 다음 결과 비교.  
<br>

*다른 분류 기법들..*  
테스트 시각에 따른 분류:  
검증(Verification) .. 만들면서 테스트 ==> 확인(Validation) .. 만든 후, 제대로인지 확인  

테스트 목적에 따른 분류: .. 위의 화이트/블랙 test와 서로 교차가 가능하다.  
고의로 실패를 유도, 시스템이 정상적 복귀를 측정하는 => 회복 test  
위험을 주어서 소프트웨어 보안이 작동하는지 보는 => 안전 test  
사용자 요구를 시스템이 어떻게 잘 응답, 처리하는지 보는 => 성능 test  
시스템 내부 구조나 코드 복잡도 등을 평가하는 => 구조 test  
버그를 수정했는데 새 버그가 발생하는지 보는 => 회귀 test (다시 문제있는 방향으로 "되돌아가다")  
기존 것과 변경 것을 동일한 입력 데이터를 넣어 비교하는 => 병행 test

분류 트리 테스트: 소프트웨어를 트리 구조로 가정.. 마치 동등분할 테스트와 유사하다고?

<u>테스트 오라클</u>이란?.. "오라클"이란 신탁?같이 미리 알려준 답/예언을 뜻함.  
따라서, 오라클과 틀리면 소프트웨어의 결함을 생각할 수 있다.  

-1. 참 오라클: 기대하는 결과를 생성 => 얘랑 틀리면 오류로 추정  
-2. 샘플링 오라클: 전부가 아닌 몇 개만 "샘플링"하여 테스트  
-3. 휴리스틱 오라클: 샘플링에서 개선된 건데.. 나머지 값은 인간이 추론(휴리스틱)하여 처리  
-4. 일관성 검사 오라클: sw 버전 변경 시, 이전 결과값과 동일하게 나오는지 확인하는 것  
<br>

**V 모델** 방식으로 개발 단계 => 테스트 단계로 테스트를 수행한다고 한다.  
요구사항 => 분석 => 설계 => 구현(여기가 끝..), 그리고 아래로  
단(위 테스트): 설계 최소 단위인 "모듈"에 초점을 맞춘 테스트.. 여기서 블랙/화이트 박스 테스트 수행  
통(합 테스트): 모듈의 "상호작용".. 즉 인터페이스 관련 오류 등 결함을 찾아내기 위한 것. (ex. 결제 기능)    
시(스템 테스트): 완성된 시스템 "전체"를 테스트 한다. (ex. 회원가입 -> 장바구니 -> 결제)  
인(수 테스트): 최종 사용자 or 업무 관계자가 이제 테스트. 
.. 알파: 회사 내 누가 사용자 역할(개발자 환경: 개발 회사 내부니까?)  
.. 베타: 실제 환경에서 일정 수의 진짜 사용자가 사용해봄(나중에 개발자에게 결과 전달).
