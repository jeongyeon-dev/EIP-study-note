달달달 외워야 하는 응집도와 결합도가 나오는 과목이다..  
일단 응집도는 강하게(한 모듈에 똘똘 뭉쳐 있으면 좋으니까), 결합도는 약하게(서로 엮이면 안됨)  
하는 것이 통상적으로 좋은 설계 방식이라는 것은 앎.  

여기서 "모듈"이라는 개념이 나오는데, 일종의 독립된 실체?라고 한다. 기능 만들다 보면 감이 옴.  
이 모듈의 응집도에 대해 보자면,  

예전처럼 우(리) 논 시절(엔) 통(통한) 순(대가) 기(가막혔다) 이런 방식도 있는데,  
자주 까먹으니까 개념을 좀 더 구조화 해보려고 한다. 

응집도는 그냥 무식?하게 응집시키기 보다는, 뭔가 규칙과 패턴이 있는 방식으로 뭉치는 것이  
아마 논리적으로도 타당할 것이다. 여기서,

우(연적 응집): 아무런 연관관계 없이 요소들이 뭉친 거다. 타당성이 아예 없으니 가장 별로.  
논(리적 응집): 왜 "논리적"인 응집이 낮은, 별로인 축에 속하는지 찾아 봤다.  
```
void keyboardInput();
void mouseInput();
void touchInput();
```
각각 다른 기능임에도 불구하고, "입력"이라는 것 하나(성격)로 묶어서 퉁쳤기 때문. 음?  
시(간적) < 절(차적): 시간을 기준으로 뭉치는 기준이 세워진다.  
.. 시. 쪽은 특정 시간에 우수수~ 처리 되어야 한다면 이걸 모아놓은 것,
.. 절. 쪽은 얘도 특정 시간에 해야 하는데 순차적으로 "수행"이 되는 것(아마 순서가 중요할 듯?).  
통(신적) < 순(차적): 입출력을 기준으로 요소들이 뭉치는 기준을 세운다.  
.. 통. 쪽은 다른 기능의 요소들이라도 동일한 입력값을 받아서 쓰는 경우를 뜻하고,  
.. 순. 쪽은 다른 기능?이라고 해도 각 요소들이 서로 주고 받을 수 있으면 되는 것을 뜻함.
기(능정 응집): 내부의 모든 요소들이 "하나의 기능"에 초점이 맞춰져 있다. 가장 최상일 수 밖에..

다음은 결합도..  
얘는 반대로 높아질 수록 안 좋다 => 외부의 모듈과의 연관 및 의존성이기 때문에,  
가능하면 모듈이 독립적으로 기능?해야 한다고 함.. 결합도가 높은 순으로(아래로 갈 수록 좋다):  

내(용) 결합: 다른 모듈 내부의 변수나 기능을 직접 사용한다. 사실상 내용적?으로 같지 않나.. 식  
공(통) > 외(부): 이 둘이 무언가에 "공동"으로 의존하는 형태?  
.. 공. 전역 변수 공유하는 것을 의미. 알지 않나? 파일 등에 위에 떡 하니 놓고 같이 이용.  
.. 외. "외"는 모듈 바깥의 규약. 즉, 인터페이스 "자체"를 의미한다. 규약 자체가 같다는 거.  
제(어) > 스(템프) > 자(료): 얘들은 인터페이스 "내부"를 의미한다는데..  
.. 제. 말 그대로 제어 신호와 같은 인자를 전달  
.. 스. 배열, 객체, 구조체 등의 형태를 인자로서 전달  
.. 자. 비교적 간단한 단일/복수의 데이터 전달, 가장 옅은 결합도로 추구해야 함!

공/외.에서의 인터페이스와, 제.스.자.에서의 인터페이스, 뭔 차이인가?
